# Авторизация

Сверено с `develop` `8cdc15f9` — 2026-11-27.

## Владение и активные экраны

`api` задаёт вход, регистрацию, восстановление пароля и платформенные OAuth-порты;
`domain` — правила и контракт репозитория; `data` — HTTP и запись сессии;
`impl` — общие ViewModel, Android Compose и адаптеры нативных форм.
Приложение предоставляет хранилище сессии, очистку локальных данных, аналитику,
провайдеры Apple/Google и навигацию. Авторизация не владеет корневым стеком.

Android использует feature Compose. На iOS вход, регистрация, восстановление
и вход из ссылки чекина используют SwiftUI с destination-scoped Kotlin-сессиями.
Пароль остаётся в форме и ViewModel; снимок для SwiftUI его не содержит.
Закрытие маршрута отменяет наблюдение, незавершённый OAuth и работу модели.
Строки принадлежат feature-ресурсам и нативным таблицам ru/be.

## Контракты

- Email нормализуется через `trim().lowercase()`, пароль отправляется без изменения.
- Парольный вход: `POST /api/tokens/native`. Правильный пароль при неподтверждённой
  почте отличается от неверных credentials, хотя оба ответа могут иметь HTTP 401.
  Ошибка подтверждения не создаёт локальную сессию.
- Регистрация: `POST /api/Users`; успешная парольная регистрация ожидает
  подтверждения почты и сама по себе не авторизует пользователя.
- Восстановление: `POST /api/Users/password/forgot`; завершение сброса остаётся
  веб-маршрутом. Не показывать пользователю сырые серверные диагностики.
- OAuth сохраняет сессию через тот же `SessionStore`. Google login поддерживает
  refresh token из существующего `Set-Cookie`; native refresh/logout используют JSON.
- При смене пользователя локальные данные очищаются перед сохранением новой сессии.
  Выход очищает локальные данные и делает best-effort отзыв refresh token;
  отмена coroutine остаётся отменой. Это не удаление серверного избранного.
- Android Google launcher получает Activity через `LocalActivity`, в том числе
  внутри локализованного Context wrapper. Пустой client ID скрывает провайдера;
  Debug/Sandbox не подтверждают реальный Google OAuth.
- iOS доступность Apple/Google зависит от конфигурации и capabilities подписанного
  приложения. Keychain должен использовать разрешённую конкретную access group;
  проверка исходников не заменяет проверку entitlements подписанного IPA.

Продолжение чекина принадлежит `Navigator`: после успешного входа исходная кофейня
открывается один раз; отмена и уход гостя очищают запрос. Внутри нативного flow
поля сохраняются при переходах вход → регистрация → восстановление. Корневой
стек меняется после завершения закрытия исходного контроллера.

## Где проверять

- [Общие модели и Android UI](impl/src/), [HTTP и токены](data/src/commonMain/),
  [контракты](domain/src/commonMain/).
- [Нативные экраны](../../iosXtool/CoffeePeek/Sources/CoffeePeek/) и
  [iOS composition](../../composeApp/src/iosMain/).
- Регрессии находятся в `domain`, `data`, `impl` commonTest/iosTest и app tests:
  неподтверждённая почта, отмена запросов, смена аккаунта, OAuth и продолжение чекина.
  Текущий набор Native selectors задаёт
  [ios-verify.yml](../../.github/workflows/ios-verify.yml).

Для изменения логики выполняются затронутые unit/contract suites и Android
assembly с packaged DEX checks; нативный код проверяется macOS CI. Ручные gates:
клавиатура/AutoFill, Back/Cancel, оба языка и темы, Dynamic Type/VoiceOver,
системный OAuth chooser и запись сессии в подписанном приложении. Реальный вход
и письма требуют безопасного тестового аккаунта. Обновление этого руководства
не выполняло эти проверки заново; старые журналы сборок доступны в Git history.
