# Черновики релизов CoffeePeek

1. В **Actions** откройте запуск сборки из `main`, которую выбрали для выпуска.
   Для Android используйте **Android Release** с успешным `build_apk`, для iOS
   — **iOS TestFlight** с успешным `upload`. Скопируйте URL или ID запуска.
2. Откройте **Actions → Draft mobile release → Run workflow** на ветке `main`.
   Выберите `android` или `ios` и вставьте URL или ID в `build_run`.
3. Откройте черновик по ссылке в Summary. Заполните «Что нового» и проверьте
   номер сборки, коммит и список PR. После выхода сборки в production нажмите
   **Publish release** в **Releases**.

Workflow берёт SHA из выбранного запуска. Версия и номер сборки вычисляются по
настройкам этого коммита и его истории. Android получает тег вида
`android-v1.2.0.2847`, iOS — `ios-v1.2.0` с номером сборки в описании. Если тег
ещё не существует, SHA сохраняется в черновике как цель для тега при публикации.

GitHub генерирует список PR от последнего опубликованного релиза той же
платформы, чей тег входит в историю сборки. Первый релиз платформы задаёт точку
отсчёта для следующих. Если для версии уже есть черновик с тем же SHA,
повторный запуск вернёт его ссылку и сохранит ручные правки. Для iOS черновик с
тем же номером версии и другим номером сборки нужно обновить вручную или
удалить и создать заново с нужным запуском.

Workflow доступен после попадания файла в `main`.

По умолчанию используется встроенный `GITHUB_TOKEN`. Если GitHub отклоняет
создание черновика для старого коммита из-за прав на `.github/workflows/`,
задайте Actions secret `MOBILE_RELEASE_TOKEN` с fine-grained токеном для этого
репозитория и правами `Actions: read`, `Contents: write`, `Workflows: write`.
[Требования GitHub к правам на создание релиза](https://docs.github.com/en/rest/releases/releases#create-a-release).
