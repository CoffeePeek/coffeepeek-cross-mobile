# Профиль другого пользователя

Профиль открывается по аватару или нику автора чекина в ленте, карточке кофейни
и списке её чекинов, а также по ссылке `https://coffeepeek.by/users/{slug}`.
Маршрут хранит серверный slug; ник и аватар из ленты служат только для шапки
во время загрузки. Кнопка «Поделиться» использует canonicalPath ответа сервера.

Новая функциональность находится в пакетах `feature/profile` текущего
`composeApp`: `domain` содержит модели и контракт репозитория, `data` — HTTP DTO,
маппинг, `ui` — экран, состояние и ViewModel. Отдельный Gradle
модуль не нужен. Корневая навигация и DI остаются в модуле композиции приложения.

Реальные данные:

- `GET /api/Users/{slug}`: `userName`, описание, аватар и публичный адрес.
  Четыре счётчика используют `checkInCount`, `addedShopsCount`,
  `addedRoastersCount`, `followersCount` с исходным серверным смыслом.
  Email, телефон и город публично не читаются.
- `PUT/DELETE /api/Users/{slug}/follow`: JWT; прямой ответ
  `{ followersCount, isFollowing }` определяет состояние кнопки и число
  подписчиков. Гостя кнопка переводит ко входу. Повторные нажатия блокируются
  до завершения запроса; смена аккаунта отменяет запросы старого зрителя.
- `GET /api/Users/{slug}/followers|following`: публичные списки с `page` и
  `pageSize`, вкладками, повторной загрузкой и переходом в выбранный профиль.
- `GET /api/v1/profiles/{slug}/favorites`: всё публичное избранное владельца,
  включая напитки. Кофейни и обжарщики используют общие карточки каталога;
  дополнительные сведения загружаются через существующие репозитории.
  Сохраняются серверный порядок, `name`, `coverPhoto` и публичные ссылки.
  У напитка есть только стабильный `drink.slug`, ссылка на страницу не создаётся.
- `GET /api/v1/profiles/{slug}/activity`: выбранный месяц, `year` 2000–2100 и
  `timeZone=Europe/Minsk`. Дни и число чекинов берутся из ответа сервера.
  При смене месяца предыдущая сетка скрывается до ответа нового запроса.
- Публичная лента с `authorSlug`: чекины пользователя, серверный порядок и cursor
  для продолжения списка. Приватные и неопубликованные записи не отображаются.

Моки профиля удалены. Разделы загружаются независимо и имеют состояния ошибки
и повтора. Пустое избранное и пустой месяц показываются только после успешного
ответа. Отсутствующие фотографии заменяются заглушками; неизвестный статус
работы кофейни не отображается как «Закрыто». HTTP 404 очищает недоступный профиль.

Все запросы идут через настроенный Gateway. На сервере для slug необходимы
`PublicAddresses__Enabled` в Account и выполненный backfill публичных адресов.
Публичные разделы запрашиваются с `Cache-Control: no-store`.

Сохранение **собственного** избранного выполняется отдельно через контракт
`/api/v1/favorites`: GET списка, PUT/DELETE `{kind}/{slug}`, где kind —
`coffee_shop`, `roaster` или `drink`. Серверные названия и фотографии сохраняются,
nullable `address` напитков не заменяется фиктивным публичным адресом.
Экран чужого профиля не изменяет это избранное.

Проверки: компиляция Kotlin для Android и iOS Arm64; unit-тесты контрактов,
состояний ошибок, пагинации, смены аккаунта и ответов старых запросов.
Android UI-тесты проверяют обе темы, ник, статистику, подписку, названия разделов,
активность, переходы к кофейне/обжарщику/подписчику и пагинацию чекинов.
Итог проверки: 297 unit-тестов и два Android UI-теста прошли; Android и iOS Arm64
скомпилированы. Фотографии в UI-фикстурах могут отсутствовать — это проверяет
штатную заглушку, production использует `coverPhoto` сервера.
