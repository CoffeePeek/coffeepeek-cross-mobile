# План реализации «Полки»

Статус: план реализации. Дата: 27 октября 2026 года.
UX-флоу и макеты: [`SHELF_UX_FLOW.html`](SHELF_UX_FLOW.html).

Цель — личная полка с пачками кофе. Пачку добавляют сканом с кнопки «+»: на
телефоне вырезается и выравнивается её лицевая сторона, пре-модерация решает,
годится ли скан. Пачки стоят на полке во вкладке «Кофе», их переставляют
перетаскиванием. Закончившаяся пачка уходит в архив с оценкой. Данные хранятся на
сервере. Сейчас реализуем и проверяем только Android. Общий код и экраны пишем так,
чтобы iOS подключился позже отдельным этапом; его трудности описаны в разделе «iOS».

## Решения по умолчанию

Это рекомендации из UX-документа. План исходит из них; если решение другое,
меняются отмеченные этапы.

| Вопрос | Решение по умолчанию | Что меняется при другом ответе |
|---|---|---|
| Где живёт полка | Переключатель «Моя полка / Каталог» во вкладке «Кофе» | Этап 3: маршрут и место встраивания |
| Где хранить | Сервер с первого дня, как избранное | Этапы 1–2: без сервера нужна локальная БД и потом миграция; правила проекта это запрещают для избранного |
| Оценка при «Закончилась» | Спрашиваем, можно пропустить | Этап 3: одна шторка |
| Доставка моделей | MVP: U2-Net-p (4,6 МБ) в APK, MI-GAN (28 МБ) скачивается при первом скане | Этап 2: модуль загрузки моделей; оптимизация (int8, ABI) — отдельно |
| Платформы | Реализуем Android. Экраны полки — в `commonMain`, сканер — за общим интерфейсом; на iOS вариант «Пачку на полку» скрыт до этапа iOS | Раздел «iOS» |
| Выпуск | За флагом, пока не готов этап 4 | — |

## Что уже есть в проекте

- **Проба сканера** (ветка `feat/shelf-scan-probe`, только Sandbox):
  `composeApp/src/androidSandbox/kotlin/com/coffeepeek/admin/sandbox/packscan/`.
  - `imaging/` — чистое ядро на Kotlin без Android и OpenCV: подбор квада, сглаживание,
    метрики и правила пре-модерации. Сверено с Python-прототипом (IoU квадов
    0,955–0,996, те же вердикты) и покрыто юнит-тестами.
  - `PackSegmenter` (U2-Net-p) и `PackInpainter` (MI-GAN) работают на ONNX Runtime 1.31.1.
- **Шторка «+»**: `composeApp/.../ui/screen/checkins/CheckInCreateSheet.kt` — два
  варианта, «В кофейне» и «Дома». Поток: `di/homecheckin/AndroidCheckInCreateFlowRenderer.kt`.
- **Вкладка «Кофе»**: `ui/screen/main/CheckInTabContent.kt` рендерит каталог через
  `CoffeeScreenRenderer().List()`. Маршруты — `Navigator.Screen` в `ui/Navigator.kt`
  (Navigation 2).
- **Каталог кофе**: `feature/coffee`, поиск для форм — `feature/coffee/api/CoffeePicker.kt`.
- **Домашний чекин**: `feature/home-check-in`. Он уже ссылается на зерно через
  `coffeeProductSlug` или `customBeanName` и хранит `doseGrams` — основа для «С моей полки»
  и учёта остатка.
- **Дизайн-система**: шторки, кнопки, поля, `CoffeePeekDestructiveConfirmationSheet`.
  Перетаскивание есть только у фото (`CoffeePeekPhotoDragState`), общего компонента
  пустого состояния нет.
- **Бэкенд** (`../coffeepeek-backend`, ASP.NET): каталог, домашние чекины и избранное
  живут в ShopsService. Фото загружаются через MediaService по presigned-ссылкам
  с назначением (purpose), как фото чекинов (`docs/api/photos-client.md`).
- **Аналитика**: `analytics/AnalyticsEvent.kt`, экраны — `AnalyticsVisibility.kt`,
  описание — `docs/ANALYTICS.md`.

## Архитектура

Новая фича `feature/shelf/{api,domain,data,impl}` по правилам `feature/README.md`.
Сканер живёт внутри фичи: у него один потребитель, отдельный модуль или `core`
сейчас не нужны.

| Слой | Что внутри |
|---|---|
| `api` | `ShelfEntry` (маршруты для приложения), `ShelfBagPicker` для домашнего чекина (этап 5) |
| `domain` | `ShelfBag`, `ShelfRepository`, порт `BagScanner`, `PackQuality` и правила `moderate()` — это бизнес-правила, их место здесь |
| `data` | `commonMain`: чистое ядро сканера из пробы (`imaging/`), API полки, DTO, мапперы, реализация репозитория. `androidMain`: ONNX-сегментатор и MI-GAN, загрузка моделей, обёртка `BagScanner` |
| `impl` | Экраны и ViewModel'и (`MviViewModel`) в `commonMain`: полка, карточка пачки, архив, скан, форма. Платформенное — только выбор фото и вибрация, через `expect`-обёртки или порты. Регистрация навигации в `impl/navigation` |
| `composeApp` | Koin-сборка в `androidMain/di/shelf`, третий вариант в шторке «+», переключатель во вкладке «Кофе», адаптер к домашнему чекину |

Задел под iOS: всё, кроме запуска моделей и выбора фото, пишется в `commonMain`.
`BagScanner` — порт в `domain`; на Android его реализует ONNX-обвязка, на iOS позже —
Core ML или ONNX Runtime для iOS. Ядро `imaging/` не трогает платформу и компилируется
под iOS как есть. Проверку на iOS в рамках этапов 0–5 не проводим.

Правила зависимостей: `domain` не знает про ONNX, Ktor, Compose и Koin; UI видит только
`domain`; другие фичи обращаются к полке только через `api`. Связь с домашним чекином
собирает приложение, а не фичи напрямую.

### Модель пачки

`ShelfBag(id, imageUrl, name?, roasterName?, coffeeSlug?, weightGrams?, grind?,
roastedOn?, addedAt, finishedAt?, position, status, rating?, buyAgain?)`, где
`status` — `OnShelf` или `Finished`.

### Серверный контракт (предложение для бэкенда)

| Метод | Назначение |
|---|---|
| `GET /api/v1/shelf` | Пачки на полке по порядку |
| `GET /api/v1/shelf/archive?cursor=` | Архив, новые сверху, постранично |
| `POST /api/v1/shelf/photos` | Presigned-ссылка для карточки пачки (purpose `shelf-bag`) |
| `POST /api/v1/shelf/bags` | Создать пачку: ключ фото + поля |
| `PATCH /api/v1/shelf/bags/{id}` | Изменить поля или фото |
| `PUT /api/v1/shelf/order` | Новый порядок: список id |
| `POST /api/v1/shelf/bags/{id}/finish` | Закончилась: `rating?`, `buyAgain?` |
| `POST /api/v1/shelf/bags/{id}/restore` | Вернуть из архива на полку |
| `DELETE /api/v1/shelf/bags/{id}` | Удалить ошибочную пачку |

- Загружается только готовая карточка (720 px, JPEG около 100 КБ). Исходное фото с
  руками и интерьером остаётся на телефоне и удаляется после сохранения.
- Полка приватная: читать её может только владелец.
- Этап 5 добавит к домашнему чекину необязательное `shelfBagId`.

## Этапы

Вся мобильная часть идёт в одной ветке `feat/shelf-scan-probe` несколькими коммитами,
без стека PR-ов: по одному или несколько коммитов на этап. Серверная часть — отдельная
ветка в `coffeepeek-backend`. После каждого этапа Android-приложение собирается и
проверяется в Sandbox.

### Этап 0. Зафиксировать пробу

- Закоммитить текущую пробу в `feat/shelf-scan-probe` первым коммитом: «сканер в
  Sandbox», уже проверенный на устройстве.
- Перенести в `docs/` или `feature/shelf/` Python-прототипы из
  `coffee-pack-samples/output/magic/scripts/`, если их решено хранить в репозитории.
  Сами сэмплы остаются вне git.

Готово, когда коммит в ветке и юнит-тесты пробы проходят.

### Этап 1. Серверный контракт

- **В `coffeepeek-backend`:** сущность полки в ShopsService; маршруты из таблицы выше;
  назначение `shelf-bag` в MediaService; тесты; описание `docs/api/shelf-client.md`.
- **В мобильном репозитории:** фейковые маршруты полки в Sandbox
  (`androidSandbox/.../backend/`), чтобы этапы 2–4 можно было проверять без сервера.

Готово, когда контракт описан и смержен в бэкенд, а Sandbox отвечает на те же маршруты.

### Этап 2. Домен и данные

- Создать `feature/shelf/domain` и `feature/shelf/data`.
- Перенести ядро `imaging/` из пробы в `data/commonMain` без изменения поведения.
  Перенести юнит-тесты и добавить сверку на синтетических сценах.
- Вынести `PackQuality` и правила `moderate()` в `domain`, с тестами на пороги.
- `BagScanner` в `data/androidMain`: сегментация, квад, выравнивание, MI-GAN,
  сглаживание, метрики. Результат — `BagScanResult(card, quality, verdict, timings)`.
- Загрузка MI-GAN при первом скане: размер, прогресс, проверка контрольной суммы,
  повтор при обрыве. U2-Net-p — в assets.
- API полки, DTO, мапперы и `ShelfRepository` с кэшем в памяти и отменой запросов
  при смене аккаунта, как в избранном.
- Оптимистичная перестановка и «Закончилась»: интерфейс меняется сразу, при ошибке
  сервера откатывается с сообщением.

Готово, когда домен и данные покрыты юнит- и контрактными тестами, а Koin-граф
собирается в DI-тесте.

### Этап 3. Полка, карточка, архив

- **Переключатель «Моя полка / Каталог»** во вкладке «Кофе»
  (`CoffeePeekCapsuleSegmentedControl`). Выбор запоминается; гость видит приглашение войти.
- **Экран полки:** полки по три пачки, выравнивание по нижнему краю, сводка сверху,
  пустое состояние.
- **Перетаскивание:** долгое нажатие с вибрацией, сдвиг соседей, автопрокрутка у края,
  зона «Закончилась». Основа — существующий `CoffeePeekPhotoDragState`; если сетке его
  не хватит, расширить его, а не подключать библиотеку.
- **Доступность:** у каждой пачки есть действия «Выше», «Ниже» и «Закончилась»
  для TalkBack.
- **Шторка «Закончилась»:** оценка, «Куплю ещё / Больше не возьму», «Пропустить»,
  снекбар с отменой.
- **Карточка пачки** (лист на 0,9 высоты): данные, меню «⋯» (изменить, переснять,
  закончилась, удалить с подтверждением).
- **Архив:** группы по месяцам, поиск, «Вернуть на полку».
- Превью светлой и тёмной темы для каждого экрана с фейковым состоянием.

Готово, когда в Sandbox работают полка, перестановка, «Закончилась» с отменой,
архив и удаление; проверены обе темы, крупный шрифт и TalkBack.

### Этап 4. Скан и добавление

- **Шторка «+»:** заголовок «Что добавим?» и вариант «Пачку на полку» в
  `CheckInCreateSheet`. Из вкладки «Кофе / Моя полка» он выбран заранее.
- **Источник фото:** системная камера (`TakePicture` через `FileProvider`) и галерея
  (`PickVisualMedia`). В основном приложении разрешение CAMERA уже запрашивается —
  используем существующий путь `ImagePicker`.
- **Экран обработки:** рамка на фото, этапы с галочками, «отклеивание» карточки.
- **Вердикт:**
  - «Принято» — форма;
  - «С подсказкой» — форма с плашкой;
  - «Переснимите» — причина, советы, «Переснять» и «Выбрать другое фото».
- **Форма:** поиск по каталогу через `CoffeePicker`, своё название, обжарщик, вес,
  помол, дата обжарки, «Заполню позже».
- **Сохранение:** загрузка карточки, создание пачки, пачка встаёт первой, снекбар
  «Заварить чашку».
- **Повтор пачки:** «Такая уже есть. Добавить вторую?»
- **Аналитика** (раздел ниже), снять флаг.

Готово, когда весь сценарий 1 из UX-документа проходит в Sandbox на всех 19 сэмплах
(вердикты совпадают с пробой), а на Debug — одна живая пачка с явного разрешения
(создание и удаление).

### Этап 5. Связи

- **«С моей полки»** в выборе зёрен домашнего чекина через `ShelfBagPicker` из `api`;
  сохраняется `shelfBagId`.
- **Остаток:** вес пачки минус дозы домашних чекинов с ней; подсказка «Похоже, пачка
  заканчивается».
- **Ручная правка углов** при «Переснимите»: 4 угла, дальше обычный путь.
- **Каталог:** «Есть на полке» и «Добавить на полку» в карточке кофе; «Купить снова»
  в архиве через `CoffeeOffer`.
- **Сводка архива** за год.
- **Строка «Полка»** в профиле.

### Этап 6. Потом

- Своя камера с живыми подсказками до съёмки.
- Распознавание текста на пачке для названия и обжарщика.
- Публичная полка, напоминания о свежести по дате обжарки.
- Оптимизация моделей: MI-GAN в int8, только нужные ABI в direct APK.

## iOS: отдельный этап после Android

На iOS полка без сканера заработает почти бесплатно: экраны в `commonMain`, данные
на сервере. Пачки, добавленные на Android, видны на iPhone, их можно переставлять и
убирать в архив. Основная работа — сканер. Ниже трудности, которые ждём.

### Запуск моделей

| Трудность | Подробности | Как снимать риск |
|---|---|---|
| Нет готового рантайма | `onnxruntime-android` на iOS не работает. В проекте нет CocoaPods и ML-зависимостей SPM; фреймворк Kotlin статический (`isStatic = true`), оболочка `iosApp` тонкая | Сканер — порт `BagScanner`; iOS-реализация на Swift регистрируется в Koin из `iosApp` или через cinterop |
| Выбор движка | ONNX Runtime для iOS: те же модели, но десятки МБ к бинарнику и обвязка C API. Core ML: рантайм в системе, Neural Engine, но модели надо конвертировать | Первый шаг этапа — прототип: конвертировать обе модели в Core ML и прогнать 21 фото |
| Конвертация MI-GAN | `migan_pipeline_v2` содержит свою обработку до и после сети (кроп вокруг маски, смешивание). coremltools может не принять эти операции | Конвертировать только генератор, кроп и смешивание перенести в общий Kotlin |
| Другая сегментация | Apple Vision (`VNGenerateForegroundInstanceMaskRequest`, доступна при iOS 18 в проекте) бесплатна, но её маски отличаются от U2-Net-p | Предпочесть U2-Net-p через Core ML ради одинаковых вердиктов; Vision — запасной вариант с отдельной калибровкой порогов |
| Расхождение результатов | Core ML на Neural Engine считает в float16: маски и квады чуть отличаются от Android | Сверка на тех же сэмплах тем же способом, что Kotlin с Python (IoU квадов, совпадение вердиктов) |

### Производительность и память

- Kotlin/Native медленнее JVM на плотных циклах по массивам: подбор квада и
  сглаживание надо замерить на iPhone. Если медленно — уменьшить сетку или вынести
  горячие места (размытие, Canny) на Accelerate/vImage за тем же интерфейсом.
- iOS жёстче завершает приложения за перерасход памяти. Пик MI-GAN на десктопе около
  0,5 ГБ, плюс Compose и картинки — рискованно для iPhone с 4 ГБ. Меры: модель
  загружается только на время скана, картинки уменьшаются до входа, при нехватке —
  вердикт «Переснимите», а не падение. Крайний вариант — entitlement
  `com.apple.developer.kernel.increased-memory-limit`.
- Сборщик мусора Kotlin/Native и большие `FloatArray`: следить за копиями плоскостей,
  переиспользовать буферы в горячих местах.

### Модели и App Store

- Скачивать MI-GAN после установки можно: это данные, а не код (правило 2.5.2 про
  исполняемый код). Штатные способы — Background Assets или On-Demand Resources;
  Core ML-модель можно скомпилировать на устройстве.
- Размер: Core ML не добавляет рантайм; ONNX Runtime добавляет десятки МБ к приложению.

### Фото

- Тексты `NSCameraUsageDescription` и `NSPhotoLibraryUsageDescription` сейчас про кофейни
  и отзывы — расширить на пачки, App Review сверяет их с реальным использованием.
- Камера iPhone отдаёт HEIC с EXIF-поворотом: перед сканом привести ориентацию к норме
  (на Android это делает `ImageDecoder`).
- Использовать существующий `PhotoSourceSheet.ios.kt`; PHPicker не требует доступа ко
  всей галерее.

### Интерфейс

- Перетаскивание по долгому нажатию в сетке рядом с системным жестом «назад» от края
  экрана: проверить, что жесты не конфликтуют.
- Вибрация при подъёме пачки: `UIImpactFeedbackGenerator` через платформенную обёртку,
  если общий `HapticFeedback` Compose на iOS окажется слабым.
- VoiceOver: действия «Выше / Ниже / Закончилась» сделаны семантическими действиями
  Compose; их поддержку на iOS подтвердить (в общем коде проекта таких действий пока нет).
- Удаление пачки — системный action sheet через существующий `NativeActionSheet`;
  меню «⋯» — `PlatformMenuButton` (`UIMenu`).

### Порядок работ на iOS

1. Включить полку без сканера: показать экраны, проверить жесты, VoiceOver и темы.
2. Прототип Core ML: конвертация U2-Net-p и генератора MI-GAN, прогон 21 фото, сверка с
   Android, замер времени и памяти на iPhone.
3. По результату выбрать Core ML, ONNX Runtime для iOS или Vision + MI-GAN; реализовать
   `BagScanner`, доставку модели и нормализацию фото.
4. Открыть вариант «Пачку на полку» на iOS.

## Проверка

- **Юнит:** ядро сканера, правила пре-модерации, редьюсеры ViewModel'ей, мапперы DTO,
  оптимистичные действия с откатом.

- **Sandbox вручную:** все сценарии UX-документа; светлая и тёмная тема, крупный шрифт,

## Риски

| Риск | Мера |
|---|---|
| Пик памяти MI-GAN (~0,5 ГБ на десктопе) на слабых телефонах | Замер на устройстве; сессия ONNX создаётся на время скана и закрывается; без арены аллокатора; при нехватке памяти — «Переснимите» вместо падения |
| Размер приложения: ONNX Runtime ~34 МБ на arm64 | Play раздаёт по ABI; для direct APK — фильтр ABI на этапе оптимизации |
| Пороги пре-модерации подобраны на 21 фото | `shelf_scan_result` в аналитике и перекалибровка после первых недель |
| Перетаскивание в сетке без готового компонента | Расширить `CoffeePeekPhotoDragState`; кнопочные действия как запасной путь |
| Сервер не готов к этапам 3–4 | Фейковые маршруты Sandbox из этапа 1 |
| Загрузка MI-GAN срывается | Повтор, продолжение докачки; скан без дорисовки допустим, если `repaintShare` мал |
