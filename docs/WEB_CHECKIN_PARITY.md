# Веб: паритет флоу чекинов с Android

Источник: текущий код Android/KMP на коммите `d168765` (14.10.2026). Этот документ — задание для веб-команды. Реализуйте **оба** вида чекина, публичную ленту и историю в профиле по описанным ниже состояниям. Сверяйте интерфейс с запущенным Android-приложением на одинаковых данных, размере viewport и теме; код задаёт размеры и поведение, но сам по себе не заменяет контрольные скриншоты.

## 1. Маршруты и сценарии

1. В нижней навигации Android есть «Поиск», «Кофе», «Лента», «Профиль», «Настройки». Кнопка `+` для чекина находится над нижней панелью на экранах поиска/кофе/ленты; в профиле — на экране «Чекины». Гость по нажатию переходит на вход.
2. Авторизованному пользователю открывается нижний лист «Новый чекин» с вопросом «Где вы пили кофе?». По умолчанию выбран вариант «В кофейне»; второй вариант — «Дома». Кнопка «Продолжить» открывает соответствующий путь. Выбор — одна радиогруппа.
3. **В кофейне:** экран «Выберите кофейню» → поиск/«Рядом со мной»/«На карте» → карточка кофейни → «Продолжить» → лист формы → отправка → экран результата. При ошибке остаются форма и черновик. Черновик живёт в течение процесса приложения для той же кофейни; выбор другой кофейни начинает новый. Вебу нужен аналог в пределах текущей сессии вкладки.
4. **Дома:** в том же листе открывается форма «Кофе дома». После сохранения она закрывается; запись видна в «Профиль → Чекины». Домашнюю запись можно открыть, редактировать и удалить с подтверждением.
5. **Лента:** публичные чекины кофейни и дома приходят из `/api/v1/feed` в порядке сервера. До одобрения модерацией публичный чекин остаётся доступным владельцу в «Чекинах», но не появляется в публичной ленте. В текущем Android-экране ленты нет видимого переключателя «публичные/мои»; «Мои чекины» находятся в профиле.
6. **Профиль:** строка «Чекины — В кофейнях и дома» ведёт на общий экран «Чекины». Счётчик в шапке подписан «В кофейнях» и тоже ведёт на общий экран. Сегменты общего экрана: «Все», «В кофейне», «Дома». Сначала календарь, затем записи по дням; домашние и кофейные записи сортируются совместно по дате и времени убыванию.

Источники: `ui/screen/main/MainScreen.kt`, `ui/screen/main/CheckInTabContent.kt`, `ui/screen/checkins/CheckInCreateSheet.kt`, `ui/screen/shop/CheckInShopPickerScreen.kt`, `ui/screen/profile/ProfileScreen.kt`, `ui/screen/checkins/ProfileCheckInsScreen.kt`, `ui/Navigator.kt` в `composeApp/src/commonMain/kotlin/com/coffeepeek/admin/`.

## 2. Точный состав интерфейса

### Общая тема и нижний лист

- Шрифт Manrope (Light, Regular, Medium, SemiBold, Bold, ExtraBold); базовая типографика Compose: заголовок 24/20 sp, основной текст 16/14 sp, подписи 13/12 sp. Межстрочный интервал основного текста 1,5. Размеры интерфейса ниже даны в dp; для CSS сопоставляйте их с логическими пикселями при одинаковом viewport и системном масштабе шрифта.
- Светлая тема: фон `#FAFAF9`, поверхность `#FFFFFF`, основной текст `#1C1917`, вторичный `#78716C`, граница `#E7E5E4`. Тёмная: фон `#1A1412`, поверхность `#2D241F`, основной текст `#FFFFFF`, вторичный `#A39E93`, граница `#3D2F28`. Акцент `#EAB308`, ошибка `#EF4444`.
- Шаг сетки 4 dp; часто используются 8, 12, 16, 24 dp. Обычная карточка: радиус 16 dp. Кнопки и однострочные поля: высота 44 dp, скругление до «капсулы».
- Лист выбора: горизонтальные поля 16 dp; варианты имеют минимум 72 dp по высоте, радиус 16 dp, границу 1 dp; выбранный вариант получает золотую границу и фон с прозрачностью 8%. В листе сверху заголовок и подзаголовок, затем две карточки и кнопка.
- Экран выбора кофейни имеет строку фильтров, поле «Поиск кофеен», список карточек либо карту. Пустой результат: «Кофейни не найдены»; ошибка даёт «Попробовать снова».

### Форма «В кофейне»

Нижний лист ограничен 76% высоты окна, содержимое прокручивается. Порядок элементов: заголовок «Чекин» и имя кофейни; три оценочные карточки «Кофе», «Сервис», «Атмосфера» с маскотами и пятью звёздами; «Дата посещения»; необязательная заметка; необязательные фото; необязательный напиток; переключатель «Сделать публичным»; ошибка отправки; кнопка «Чекин». Оценки начинают с **4/5 каждая**, видимость — **Private**, дата — сегодня. Поля идут по вертикальной линии с точками; необязательные шаги имеют пунктирную линию. Для фото показываются плитки 96×96 dp, счётчик `Добавлено: N/5`, кнопка добавления и удаление с мини-кнопкой на углу. Напиток выбирается из каталога; `other` открывает поле свободного названия.

Дата не может быть в будущем. Заметка до 1000 символов, фото до пяти, оценки каждой категории 1–5, название другого напитка 1–100 символов. На сохранении лист нельзя закрыть. В состоянии отправки показываются индикатор 88 dp, «Отправляем чекин…» и «Сохраняем ваш кофейный момент». Успех: иконка 88 dp, «Чекин создан!», сообщение по выбранной видимости, кнопки «К ленте» и «Мои чекины». Для Public текст сообщает о проверке до появления в ленте; для Private — что запись видна только владельцу.

**Обновление от 15.10.2026:** в формах кофейни и домашнего приготовления восстановлено выделение объекта из первого нового фото. Полное фото остаётся в `photos`, отдельный прозрачный PNG передаётся в `drinkPhoto`. При нескольких объектах пользователь выбирает чашку; обработку можно повторить или пропустить. Во время обработки и до выбора из нескольких объектов отправка недоступна. Ошибка выделения позволяет сохранить оригинал без вырезки; ошибка загрузки выбранной вырезки останавливает отправку. При редактировании сохранённые фото остаются без изменений. См. `CHECK_IN_DRINK_PHOTO.md`.

### Форма «Дома»

Сверху «Кофе дома», закрытие, переключатель видимости и одна оценка «Как получился кофе?» (новая запись начинает с **5/5**). Далее: дата приготовления; необязательные способ заваривания, зерно, количество кофе в граммах, время в минутах и секундах, заметка, название напитка и фото (до пяти). Внизу закреплена кнопка «Сохранить чекин». Выбор зерна открывает отдельный поиск: первая страница сразу, задержка поиска 300 мс, возможность «Использовать своё зерно». ## 3. HTTP-контракты

Все вызовы к API используют configured base URL; защищённые операции передают сессию (`Authorization: Bearer …`). Для обычных JSON-ответов проверяйте и HTTP-код, и оболочку `{ "isSuccess": true, "data": ..., "message": ... }`. Не считайте успешным ответ без `data` или без `id` созданного кофейного чекина. Строки дат — ISO 8601; показывайте время в локальном часовом поясе пользователя. Не конструируйте URL защищённых фото: берите адрес из ответа, относительный URL разрешайте относительно API base URL.

| Операция | Запрос | Контракт |
|---|---|---|
| Выбор кофейни | `GET /api/CoffeeShops?page=1&pageSize=20[&q=…]`; детали `GET /api/CoffeeShops/{id}` | Для создания передавайте **`shop.publicAddress.slug`** как `coffeeShopSlug`, не ID карточки. Близлежащий поиск использует `POST /api/v1/coffee-shops/search`; карту можно открыть как альтернативу списку. |
| Напитки | `GET /api/catalogs/drinks` | Массив `{slug,nameRu,nameEn}`. `slug="other"` требует `customDrinkName`; отсутствие напитка допустимо. |
| Способы дома | `GET /api/Catalogs/brew-methods` | Используйте текущий `slug`, отправляйте в `brewMethodCode`; исторические коды оставляйте редактируемыми. |
| Зерно дома | `POST /api/v1/coffees/search` | `{q,filters:{"availableOnly":false},page:1,pageSize:20}`; выбор отдаёт `coffeeProductSlug`, собственное зерно — `customBeanName`. При редактировании сохранённого продукта может передаваться `coffeeProductId`. |
| Фото | `POST /api/Photos/check-in` | JSON-массив `{sizeBytes,fileName,contentType}` → массив `{uploadUrl,storageKey,photoId?}`. Затем `PUT uploadUrl` сырыми байтами с правильным `Content-Type`; для домашнего пути также `x-amz-tagging: is_permanent=False`. В JSON создания передаются `{fileName,contentType,storageKey,size}`. Не отправляйте байты изображения в JSON. |
| Создать в кофейне | `POST /api/v1/check-ins` | См. поля ниже. Ответ `data` — полный `CheckInDto`. |
| Свои визиты | `GET /api/v1/check-ins/mine?pageNumber=1&pageSize=20` | `{items: CheckInDto[], totalCount}`. Для месяца `from`/`to` — UTC-границы месяца, страница до 100; догружайте все страницы, группируйте по **локальной** дате визита. |
| Создать/читать дома | `POST /api/v1/check-ins/home`; `GET /api/v1/check-ins/home?pageNumber=1&pageSize=20[&from=YYYY-MM-DD&to=YYYY-MM-DD]`; `GET /api/v1/check-ins/home/{id}` | Ответ истории `{items,totalCount}`; дата фильтра — `preparedOn`. `GET /api/v1/check-ins/home/calendar?from=YYYY-MM-DD&to=YYYY-MM-DD` возвращает `{preparedOn,brewCount}[]`. |
| Публичная лента | `GET /api/v1/feed?pageSize=20[&cursor=…][&citySlug=…][&coffeeShopSlug=…][&authorSlug=…]` | `Cache-Control: no-store`; `{items:[{publishedAtUtc,checkIn}],nextCursor}`. Сохраняйте серверный порядок, догружайте по `nextCursor`; при 400 с курсором начните пагинацию заново. |
| Редактировать визит | `PUT /api/v1/check-ins/{id}` | `{text,rating,drinkSlug,customDrinkName}`; фото и видимость не включаются. |
| Видимость визита | `PUT /api/v1/check-ins/{id}/visibility` | `{visibility:"Private"|"Public"}`; берите возвращённые `visibility` и `moderationState`. |
| Лайк и жалоба | `PUT`/`DELETE /api/v1/check-ins/{id}/helpful`; `POST /api/v1/check-ins/{id}/reports` | Лайк без body, ответ `{isHelpful,helpfulCount}`. Жалоба `{text}` (обрезать пробелы), успех HTTP 201. |
| Домашние изменения | `PUT`/`DELETE /api/v1/check-ins/home/{id}` | PUT содержит редактируемые поля создания, **без** `photos` и `drinkPhoto`; DELETE после подтверждения. |

Пример тела для визита (значения иллюстративные, названия полей — точные):

```json
{

  "visitedAt": "2026-10-14T06:00:00Z",
  "text": "Отличный фильтр",
  "rating": { "place": 4, "service": 5, "coffee": 5 },
  "visibility": "Public",
  "drinkSlug": "other",
  "customDrinkName": "Фильтр",
  "photos": [{ "fileName": "coffee.jpg", "contentType": "image/jpeg", "storageKey": "check-ins/photo.jpg", "size": 120000 }],
  "drinkPhoto": null
}
```

Пример тела для домашнего приготовления:

```json
{
  "preparedAt": "2026-10-14T09:00:00+03:00",
  "preparedOn": "2026-10-14",
  "brewMethodCode": "hario-v60",
  "coffeeProductSlug": "example-beans",
  "coffeeProductId": null,
  "customBeanName": null,
  "doseGrams": 18.5,
  "brewDurationSeconds": 180,
  "tasteScore": 5,
  "text": "Шоколад и ягоды",
  "drinkSlug": "other",
  "customDrinkName": "Фильтр",
  "photos": [],
  "drinkPhoto": null,
  "visibility": "Private"

```

`POST /api/v1/check-ins` отправляет `coffeeShopSlug`, `visitedAt`, `text`, `rating:{place,service,coffee}`, `visibility:"Private"|"Public"`, `drinkSlug`, `customDrinkName`, `photos[]`; транспорт также допускает отдельное необязательное `drinkPhoto`. `rating` и напиток по API могут отсутствовать, хотя действующая Android-форма всегда предлагает три оценки. **Исправлено 15.10.2026:** `visitedAt` — полный момент визита в UTC с часами, минутами и секундами. Новый черновик запоминает текущее время; выбор другого дня сохраняет локальное время черновика и учитывает часовой пояс выбранной даты. UTC-полночь из date picker служит только идентификатором календарного дня, её нельзя отправлять вместо фактического времени визита. Старый клиент обнулял время до локальной полуночи; исходное время таких записей автоматически не восстановить. Бэкенд принимает `DateTimeOffset` и сохраняет `UtcDateTime` без обрезания времени. Подтверждайте создание только после корректного ответа сервера. При сетевом обрыве после POST сообщайте, что результат неизвестен, и предложите проверить «Мои чекины» до повтора: запрос мог успеть выполниться.

`POST /api/v1/check-ins/home` отправляет `preparedAt` (ISO с `Z`/offset), `preparedOn` (`YYYY-MM-DD`), `brewMethodCode`, `coffeeProductSlug` либо `customBeanName`, `doseGrams`, `brewDurationSeconds`, `tasteScore`, `text`, `drinkSlug`, `customDrinkName`, `photos[]`, отдельный `drinkPhoto`, `visibility`. При редактировании той же записи вместо выбора нового зерна может передаваться сохранённый `coffeeProductId`; при создании это запрещено локальной валидацией. При обычном создании без вырезки `drinkPhoto=null`. Серверный ответ содержит `preparedAtUtc`, `preparedOn`, `visibility`, `moderationState`, `photos`, необязательный `drinkPhoto`. Не объявляйте публикацию подтверждённой, если ответ не вернул `visibility`; при редактировании неизвестной видимости не отправляйте новое значение до выбора пользователя.

`CheckInDto` для ленты и своих визитов: `id`, `kind` (`Shop`/`Home`), `shop`, `author`, `username`, `shopName`, `text`, `createdAtUtc`, `visitedAt`, `rating`, `visibility`, `moderationState`, `contentRevision`, `rejectionReason`, `photos[{id,url,sortIndex}]`, `drinkSlug`, `customDrinkName`, `drinkNameRu`, `drinkNameEn`, `helpfulCount`, `isHelpfulByCurrentUser`, `drinkPhotoUrl`, `home{preparedOn,brewMethodCode,beanName,doseGrams,brewDurationSeconds,tasteScore}`. Для старых записей часть полей отсутствует/null; `kind=Home` включает блок рецепта. Массив обычных фото сортируется по `sortIndex`. Сохраняйте статусы Private / Pending / Approved / Rejected из ответа; домашняя карточка профиля показывает их человекочитаемые названия. Публичная лента показывает только опубликованное сервером. Текущий общий экран профиля не рисует отдельный бейдж модерации на карточке визита в кофейню; не добавляйте его ради единообразия.

Домашние ограничения до отправки: дата корректна и не позже текущего времени более чем на 5 минут; `preparedOn` соответствует ближайшему локальному дню; код способа — slug до 100 символов; зерно выбирается одним способом, своё название до 250 символов; доза `0.01..10000` г с максимум двумя десятичными знаками; время `1..604800` секунд; оценка `1..5`; текст до 1000; другое название напитка `1..100`; не более пяти **разных** фотографий. Введённая пользователем десятичная запятая превращается в точку для API. При ответе 400/422 отображайте ошибки у полей; 401 ведёт к повторному входу, 403/404/409/429 и 5xx показываются как отдельные состояния без потери формы.
